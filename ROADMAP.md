# Roadmap

## v0.1 — Public experimental baseline

- Publish lightweight EGASE principles.
- Publish QSEM and EAR specifications.
- Publish machine-readable starter schemas.
- Publish one anonymized methodological case study.
- Establish a privacy-by-abstraction rule for future case studies.

## v0.2 — Independent validation

- Apply the method to a second independent software project.
- Measure human intervention frequency, repeated agent cycles, rework, defects, evidence quality, and governance cost.
- Record failures without tuning the method to force a positive result.
- Refine Reasoning Preservation and proportional governance heuristics only when evidence supports a change.

## v0.3 — Tooling

- Reference verifier for QSEM and EAR manifests.
- Example CI integration.
- Conformance profiles only if they remain lightweight and useful.

## Research track

- Standards crosswalk with explicit separation of conceptual alignment, practical compatibility, and formal conformance.
- Empirical evaluation across multiple independent projects.
- Public technical paper / white paper.
- DOI-backed release when the method is stable enough to cite.

## Guardrail

The roadmap must not turn the project into the failure mode it studies. A proposed control or artifact should be rejected when its cost is not proportional to the risk or learning it produces.
